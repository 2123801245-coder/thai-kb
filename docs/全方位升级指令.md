## 1. 第一步：核对事实基线（禁止跳过）

### 1.1 源码与运行副本已经不同步

| 文件 | 源码 | 运行副本 |
|---|---|---|
| `泰语个人知识库.html` | `../泰语个人知识库.html`（105,626 B） | `apk/www/泰语个人知识库.html`（92,662 B） |
| `sw.js` | 根目录有（5,661 B） | `apk/www/sw.js` **不存在** |
| `js/home.js` `js/review.js` `js/shell.js` | 有 | **不存在** |

结论：`apk/www/` 是**旧构建**，缺 3 个 JS 模块和 Service Worker。而 `js/pwa.js` 会去 `register('sw.js')` —— 当前实际返回 404，**PWA 离线是坏的**。

→ 升级以**根目录源码**为唯一事实来源。`apk/www/` 视为构建产物，不手工编辑。

### 1.2 重复副本污染

`apk/www/` 下有 13 个 Finder/iCloud 复制品，全部是垃圾：`books 2/`、`css 2/`、`data 2/`、`fonts 2/`、`icons 2/`、`js 2/`、`media 2/`、`build-info 2.js`、`manifest 2.webmanifest`、以及 4 个 `… 2.command/.bat`。

### 1.3 首屏被 64 MB 语音脚本拖死

- `data/voice.js` = **9.14 MB**
- `data/voice-lessons.js` = **58.47 MB**
- 两者都是同步 `<script src>`，在 `<head>` 后顺序加载完才渲染

这是当前**最大的性能问题**，也是手机上「打开很慢」的根因。

### 1.4 数据格式与注释不一致

`js/data.js` 的注释说数据在 `data/*.json`，实际全是 `data/*.js`（挂全局变量的 JS 文件）。要么统一成 JSON + 运行时 fetch，要么把注释改成事实。

## 2. 硬约束（触碰任何一条即为失败）

1. **零后端**。不允许引入服务器、数据库、账号体系。
2. **`file://` 双击必须能用**。离线版文件夹直接双击 HTML 打开时，核心功能（查词、读课文、听发音、看笔记）不得崩。Service Worker 在 file:// 下不注册，这是已知且允许的降级。
3. **数据向后兼容**。老用户的 `localStorage`（`kb_my_words`、`kb_my_patterns`、`spd`、掌握度、错题本）必须能平滑迁移；迁移失败要留原数据，不能丢。
4. **APK 内的 WebView 必须照常工作**。不依赖新的浏览器 API 而不做降级。
5. **不联网也能用**。任何新增的在线能力（字体、AI、词典）都必须有离线兜底。
6. 保持现有视觉语言与信息架构。这是学习工具，不是展示页——**不要做视觉炫技式改版**。

## 3. 升级范围

按优先级执行。**每一项做完先自测再进入下一项**，不要一口气全改。

### P0 — 修复正确性（必须先做）

**P0-1 源码与构建对齐**
- 查明 `apk/www/` 的生成方式（`tools/release.js`？`一键发版（Mac）.command`？），让构建流程自动带上 `sw.js` 与全部 JS 模块。
- 加一个**构建自检**：扫 HTML 里所有 `<script src>` 与 `<link href>`，逐个确认文件存在，缺一个就报错退出。

**P0-2 修好 Service Worker**
- 让 `sw.js` 真正可用：静态资源预缓存、导航请求走 network-first fallback 到 cache、版本号变更时清旧缓存。
- 验收：断网后刷新，页面正常打开，词表/课文/发音都在。

**P0-3 清理重复副本**
- 删掉 1.2 列出的 13 个 `… 2` 项。删前先确认它们是空目录或与主目录内容完全一致（用 diff 验证，别凭名字猜）。

### P1 — 性能（用户可感知最强）

**P1-1 语音按需加载**
- 首屏只加载**词表语音索引**（id → 偏移/长度），不加载音频本体。
- 点击发音时再取对应片段；取过就进 IndexedDB 缓存，二次点击零延迟。
- 离线场景允许一次性后台预加载整包（设置里给开关，或 Wi-Fi 下自动）。
- 验收：冷启动到可交互的时间对比改造前有数量级下降（目标 <2s，桌面；<3s，手机），且「点一下就能响」的体验不变。

**P1-2 脚本加载策略**
- 除首屏必需的模块外，其余改 `defer` / 动态 `import()`。
- 课文、辨析、讲解等重模块在切到对应标签页时再加载。

**P1-3 首屏资源瘦身**
- 审计 CSS/字体：泰文字体当前内嵌子集 + Noto Sans/Serif 三套，确认是否全部首屏需要。

### P2 — 数据与工程化

**P2-1 数据层统一**
- 统一 `data/` 的格式约定，并把 `js/data.js` 注释修正为事实。
- 加一个 `tools/validate-data.js`：校验每条词/课文/辨析/讲解的必填字段、id 唯一性、引用完整性（比如课文里引用的生词是否在词表里）、语音条目是否都有对应音频。构建时自动跑。

**P2-2 版本与更新**
- `build-info.js` 里落一个真实版本号 + 构建时间，界面上「关于」可查。
- APK 的「检查更新」逻辑核对一遍，确保版本比较正确。

### P3 — 学习效果（这是知识库的立身之本）

**P3-1 间隔重复**
- 现在的掌握度是手工标记。增加一个轻量 SRS：每个词记录「上次复习、下次到期、连续答对次数」，用 SM-2 或更简单的固定间隔阶梯。
- 新增「今日复习」入口，只推到期词，别一次塞 402 条。
- 与现有错题本打通：错题自动进入复习队列。

**P3-2 全局搜索**
- 一个输入框同时搜：泰语词、中文释义、课文正文、笔记、辨析。支持泰文无空格子串匹配。
- 结果按类型分组，点进去直达原文位置。

**P3-3 学习数据导出**
- 掌握度、错题本、笔记、复习记录一键导出 JSON；能导回。
- 现有 `js/storage.js` 的完整备份逻辑复用，别另起一套。

### P4 — 可用性

**P4-1 无障碍**
- 11 个 `<section class="pane">` 的标签切换补全 `role="tablist"/"tab"/"tabpanel"`、`aria-selected`、方向键切换、切页后焦点落到面板标题。
- 全站键盘可达性走一遍：Tab 序、可见焦点环、Esc 关弹层。

**P4-2 深色模式**
- 跟随 `prefers-color-scheme`，并允许手动覆盖（存 localStorage）。
- 泰文字在深色下的对比度要单独校验（黄色调容易糊）。

**P4-3 标签数量一致性**
- README 写「9 个标签页」，实际有 11 个 `pane`。以实际为准，更新文档。
