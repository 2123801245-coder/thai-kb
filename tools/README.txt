tools/ —— 发布链路（给同学的离线包）
========================================

一条命令出一版（自检 → 打包 → 压缩，任一步失败即停）：

    node tools/release.js           # 或双击仓库根目录「一键发版（Mac）.command」

等价的手工三步：

    node tools/check.js             # 先自检，硬失败不出包
    node tools/make-package.js      # → ~/Desktop/泰语知识库-发布版/
    python3 tools/make-zip.py       # → ~/Desktop/泰语知识库-离线版.zip

增量更新包（release.js 会顺手做；也可单独跑）：

    python3 tools/make-update.py    # → ~/Desktop/泰语知识库-更新包.zip
    # 比对上一版 zip 的 CRC，只装变化过的文件，给已拿到完整包的同学补丁用

改完任何东西先自检（本地与 CI 跑的是同一条命令）：

    node tools/check.js             # 硬失败时退出码 1

CI 在 .github/workflows/ci.yml：PR 与 main 上跑同一条命令；
每个 PR 都会自动验一遍解析、数据一致性、发音覆盖与发布包等价性。

结构与职责
----------------------------------------
tools/make-package.js   编排：注入 data/*.js、按引用拷媒体、渲染模板、打印事实与警告。
                        这里不该再出现任何写死的计数、说明正文或素材路径。
tools/lib/pkg-info.js   发布包的「事实」唯一来源：从 data/ 与骨架推导
                        标签页数/词数/词条数/课文数与课程分布/视频音频数，以及
                        data/ 真正引用到的媒体清单（mediaRefs）。说明文本里的每个数字
                        都来自这里；骨架里少了或多了东西，改数据即自动跟上。
tools/templates/        说明正文与启动器：使用说明.txt、手机使用指南.txt、
                        备用启动（Mac|Windows）、手机访问（Mac|Windows）。
                        正文内容直接写在这里，数字写成 {{token}}（{{words}}、
                        {{course.泰语视听说}}、{{html}}、{{htmlEncoded}}…）；
                        未知 token 会在打包时报错，不会静默印出原文。
tools/release.js        一键发版编排：check → make-package → make-zip 串起来跑，
                        任一步非 0 退出即停；最后调 make-update.py 出增量包。
tools/make-update.py    增量更新包：旧 zip 里每个文件的 CRC32 与新发布目录比对，
                        只把变化/新增的文件打进「更新包.zip」，沿用旧包顶层目录名。
                        删除过的文件不处理（不主动删同学手里的文件）。
tools/check.js          仓库自检（无需装依赖，只用 Node 内置模块）：
                        ① 骨架无内联 script、16 个模块全部可解析
                        ② data/*.json 解析 + 归类/段落/媒体引用一致性
                        ③ 词表、词汇讲解词条与例句、课文段落的发音覆盖为 0 缺
                          （页面 📌固定 写入的 pin=1 条目除外：朗读走系统/在线语音，
                          只在提示档里报数）
                        ④ 发布包等价性：真跑一次 make-package.js 到临时目录，比对
                          data/*.js 与源 json 逐字节、js/ 一致性、说明里的数字、
                          只拷引用到的媒体
                        另有「提示」一档：重复词条、meta 里没有课文的键、
                          桌面包是否已过期等，只打印不改退出码。
                        注：media/ 未入库，CI 上媒体相关检查会自动跳过并说明。
tools/make-zip.py       打 zip（Python zipfile，保证中文名带 UTF-8 标志位，
                        macOS 自带 zip 不置位，Windows 解压会乱码）。

「📌 固定到知识库」（页面 ➕添加 页的按钮）
----------------------------------------
· 实现：server.py 的 POST /api/pin（只收 127.0.0.1 本机请求），把浏览器里
  「我的添加」（生词 / 句型 / 导入课文）按 t / p / label 去重后写进 data/*.json；
  发布目录里只有打包好的 data/*.js，写完 .json 会再镜像更新同名 .js。
  lessons.json 变动时同步写 lessons.meta.json（lessonKeys / courseOf），
  归类自检才能过；前端固定成功后自动删掉本机副本，避免两处重复显示。
· 写入的条目带 "pin": 1：没有内置发音，朗读自动降级到系统泰语/在线语音；
  check.js 的发音硬检查对 pin 条目放行，只在提示里报数，不降低内置内容的标准。
· 学习进度（掌握度 / 错题本 / 笔记文字）固定时整份快照写 data-personal/progress.json：
  个人数据，三处特殊对待 —— ① .gitignore 排除，不入库；② make-zip / make-update
  压缩时跳过该目录，不随发布包分发给同学；③ make-package 重出发布目录前先把它
  搬走再放回，不会把已固定的进度删掉。浏览器清空/换设备后，loader.js 会安静读取
  这个基线自动恢复（本机已有数据则以本机为准）。笔记里的图片与附件不进快照，
  仍靠「导出备份」搬家。
· 在发布目录里固定出的内容只落在那个目录，不会自动回流仓库 data/ ——
  想随版本长期保留就到仓库入口（泰语知识库.command）里固定；
  已在发布目录固定的，发版前把它的 data/*.json 拷回仓库 data/ 即可。

为什么这么分
----------------------------------------
曾经把「10 个标签页 … 添加 / 导入」写死在构建脚本里，结果发给同学的包印着过期数字。
现在数字只有一个来源（data/ 与骨架），文本只有一处正文（templates/），
打包脚本只负责搬运；加课、加词、改标签页之后重跑两条命令即可。

已知与待办
----------------------------------------
· release.js 里增量包一步的顺序敏感：必须在 make-zip.py 之前跑
  （压缩会覆盖旧 zip，压完再比对就读不到真正的「上一版」了）。
· 说明里仍写着「请勿外传」，面向用户的命名也还是「发布版 / 离线版」（等用户定）。
· media/ 未入库（.gitignore），因此打包依赖本机 media/ 存在；缺失文件会打警告。
· zip 内顶层目录名与 zip 文件名不一致（发布版 vs 离线版），属命名问题，未动。
