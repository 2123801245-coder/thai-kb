tools/ —— 发布链路（给同学的离线包）
========================================

两条命令出一版：

    node tools/make-package.js      # → ~/Desktop/泰语知识库-发布版/
    python3 tools/make-zip.py       # → ~/Desktop/泰语知识库-离线版.zip

结构与职责
----------------------------------------
tools/make-package.js   编排：注入 data/*.js、按引用拷媒体、渲染模板、打印事实与警告。
                        这里不该再出现任何写死的计数、说明正文或素材路径。
tools/lib/pkg-info.js   发布包的「事实」唯一来源：从 data/ 与骨架推导
                        标签页数/词数/词条数/课文数与课程分布/视频音频数，以及
                        data/ 真正引用到的媒体清单（mediaRefs）。说明文本里的每个数字
                        都来自这里；骨架里少了或多了东西，改数据即自动跟上。
tools/templates/        说明正文与启动器：使用说明.txt、手机使用指南.txt、
                        备用启动（Mac|Windows）、手机访问（Mac|Windows）。
                        正文内容直接写在这里，数字写成 {{token}}（{{words}}、
                        {{course.泰语视听说}}、{{html}}、{{htmlEncoded}}…）；
                        未知 token 会在打包时报错，不会静默印出原文。
tools/make-zip.py       打 zip（Python zipfile，保证中文名带 UTF-8 标志位，
                        macOS 自带 zip 不置位，Windows 解压会乱码）。

为什么这么分
----------------------------------------
曾经把「10 个标签页 … 添加 / 导入」写死在构建脚本里，结果发给同学的包印着过期数字。
现在数字只有一个来源（data/ 与骨架），文本只有一处正文（templates/），
打包脚本只负责搬运；加课、加词、改标签页之后重跑两条命令即可。

已知与待办
----------------------------------------
· 说明里仍写着「请勿外传」，面向用户的命名也还是「发布版 / 离线版」（等用户定）。
· media/ 未入库（.gitignore），因此打包依赖本机 media/ 存在；缺失文件会打警告。
· zip 内顶层目录名与 zip 文件名不一致（发布版 vs 离线版），属命名问题，未动。
